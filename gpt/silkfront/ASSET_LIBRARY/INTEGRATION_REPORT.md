# ASSET LIBRARY — совместимость с SILKFRONT, аудит 03

Статус: **ресурсная база проекта, кандидаты для интеграции; не автоматическое принятие 41 объекта**. Игровой рендер и геометрия карт этим аудитом не изменены. Исходные юниты и библиотека не перерисованы.

## Источник и воспроизводимость

- Опубликованная библиотека: https://agentsharik.github.io/pages/asset-library.html
- Фактический репозиторий: https://github.com/AgentSharik/AgentSharik.github.io, `pages/asset-library.html`. Ссылка на HTML в задании сама по себе не является URL Git-репозитория.
- Дерево main при аудите: `4a3562025a59d279aa0ee172c12171cfb00f79e0`. Исходник сохранён без правок в `reference/asset-library.html`, URL/время/SHA-256 — `reference/SOURCE.json`.
- В HTML два script. Первый содержит примитивы SVG, генераторы и реестр `A`; второй — галерею, фильтры, копирование, загрузки, манифест и текстовые промпты. Промпты **не** являются готовыми иллюстрациями, персонажи/кампании из них не производились.
- 41 запись: 9 тайлов + 3 перехода + 15 растений + 7 каменных объектов + 7 предметов окружения. Отдельного каталога SVG в публичном дереве нет: SVG генерируются из seed на клиенте.
- Генератор `RN` детерминированный, seed хранится в каждой записи; `S(a)` кэширует результат. `SV` создаёт 256×256, тень и локальные `<defs>`. При прямом встраивании нескольких одинаковых SVG в один DOM нужны уникальные ID градиентов; загрузка отдельными текстурами этого конфликта не имеет.
- `tools/gamecheck/library-review.mjs` извлекает только первый, предварительно прочитанный script в изолированном vm без доступа к файлам/сети из SVG-кода; экспортирует исходные SVG и PNG Chromium. Не запускает clipboard/download-интеграции библиотеки.
- Все 41 пары — в `review/`; `manifest.json` сохраняет seed/категорию/опору и `accepted:false`. `metrics.json` — техническая проверка альфа-канала и границ, а не художественная оценка.

## Что проверено

Создан и открыт в браузере `review.html`: все 41 объект и Мечник в масштабе ×0.5, общая линия опоры. Дополнительно открыт `comparison.html`: десять существующих юнитов рядом с елью, валуном, бочкой и травой в пробных масштабах; 3×3 раскладка четырёх тайлов. Подтверждена полная декодировка изображений. Просмотрены ландшафт, растительность, камни/предметы. Свет слева сверху, тёмный контур, градиенты и бирюзово-фиолетовая палитра в целом совместимы с утверждённой холодной готикой. Но у окружения крупнее формы, толще контур, ярче зелёный/фиолетовый, проще детализация, чем у десяти юнитов. Это не безусловно готовый художественный комплект.

Текущий `GAME` — **Canvas 2D, не Phaser**. Для технического подключения новых изображений миграция движка не требуется. Текущие `map.js`/`world.blocked` определяют механику отдельно от изображения; сохранять это разделение.

### Масштаб, опора и перспектива

| Контракт | Юниты | Объекты библиотеки | Земля/переходы |
|---|---|---|---|
| Исходный холст | 288×288 | 256×256 | 256×256 |
| Опора | (144,228), JSON meta.pivotPx | заявлена (128,228) | точка верх-лево, не опора персонажа |
| Нормализованная опора | (0.5,0.7916667) | (0.5,0.890625) | (0,0) |
| При ×0.5 | кадр 144×144 | 128×128 | не привязывать автоматически к 32px клетки |

При одном ×0.5 ель ~107px над землёй, мечник заметно ниже; это допустимо для взрослого дерева. Но бочка при ×0.5 сопоставима по высоте с человеком (для обычной бочки слишком велика), кусты/грибы слишком велики для обычной растительности. Пробные (не принятые) масштабы: деревья 0.4–0.55, валуны 0.35–0.5, кусты 0.18–0.3, грибы 0.10–0.2, бочка 0.18–0.25, факел 0.28–0.35. Подбирать по реальному габариту, а не заполнять одинаковый квадрат. Масштаб юнитов не менять.

У пауков в STYLE_GUIDE земля сжата по Y≈0.45. Тени объектов библиотеки имеют rx/ry от 30/8 до 110/14: общего единого коэффициента проекции нет. Деревья/камни читаются как условный 3/4 RTS; некоторые стены/скалы выглядят фронтально. Совместимость перспективы **условная**, не доказанная одинаковая 3D-камера. Перерисовка юнитов ради окружения недопустима.

Реальная геометрия часто ниже y=228 (корни, ножки, тени до 240–255); указанная опора — регистрация, не нижний непрозрачный пиксель. Привязывать её к месту контакта с землёй; сортировать по контактной Y, а не верхнему краю холста. Физический footprint хранить отдельно от прозрачных полей/свечения.

### Прозрачность и обрезки

- **9 тайлов полностью непрозрачны** (65536 пикселей alpha=255), несмотря на общее описание «прозрачный фон». Это правильно для базового грунта; неправильно было бы использовать их как прозрачные накладки.
- 3 `edge_*` имеют прозрачность и мягкий рваный край. Маски используют turbulence/displacement/blur; проверены в Chromium. Это один тип края, не полный autotile-набор углов/Т-сочленений.
- 29 предметов имеют прозрачность и полупрозрачные тени/свечение. PNG без белой подложки.
- `veg_colony` касается верхней границы (светящийся узел/ореол); `veg_stump`, оба гриба — нижней; `env_fire` — нижний ореол; `env_cocoon` — верхняя нить (для подвеса может быть намеренно). Не объявлять любое касание обрезкой, но перед принятием проверить/расширить безопасные поля **новой версией**, не затирать исходник.
- У грибов генератор ставит переднюю ножку при y=216 и высоте 40, с нижним изгибом ниже 256: подтверждён риск среза геометрии. У пня корень до 250 + половина stroke 13 также выходит за холст.
- Попытка PNG-экспорта установленным `@resvg/resvg-js` аварийно завершилась на `filter/displacement_map.rs`. Самостоятельные PNG экспортированы браузером. Не запускать этот filter-path вслепую в основном artgen; не менять десять готовых атласов ради проблемы стороннего экспортёра.

## Решение по всем объектам

«Кандидат» ниже означает допустимость небольшого согласованного пробного подключения, **не художественное принятие**.

| ID / группа | Решение и роль |
|---|---|
| tile_dirt, tile_ash, tile_forest | Первые кандидаты грунта «Перевала»; нейтральные, меньше конкурируют с силуэтами. Сначала проверить повторение 3×3 на настоящем размере. |
| tile_grass | Кандидат после оценки яркости: зеленее и насыщеннее существующей земли. |
| tile_dry, tile_rock | Локальные пятна/дорога, не новая карта. Проверить контраст и размер каменных деталей. |
| tile_infected, tile_web, tile_colony | Только локальный визуальный слой у Колонии; НЕ давать скорость/регенерацию/радар без отдельной реализации и тестов. Бирюзовые линии не должны путаться с ресурсами и приказами. |
| edge_grass, edge_ash, edge_colony | Условные кандидаты после bake в PNG и проверки стыков/углов. Вращать текстуру грунта можно, вертикальные предметы — нет. |
| veg_oak_a, veg_oak_b, veg_pine | Кандидаты замены только внешнего вида существующих деревьев. Сохранить resource id, 1×1 footprint, 48 древесины, добычу и исчезновение. Крона шире footprint — проверить выделение/окклюзию рабочих. |
| veg_dead, veg_burnt, veg_web | Кандидаты редких вариантов деревьев/декора с теми же ограничениями; не создавать ложный ресурс отдельно от resource entity. |
| veg_colony | Отложить до проверки поля сверху и менее яркой читаемости: узлы конкурируют с юнитами/ресурсами. |
| veg_bush, veg_bush_dry, veg_dry_grass | Кандидаты малых неблокирующих деталей вне боевой полосы; уменьшить масштаб. Не добавлять в `world.res` и не начислять древесину. |
| veg_stump | Условный декор после проверки/исправления корня за холстом. Можно показать после depletion, не оставлять блокировку клетки. |
| veg_mushroom, veg_glow_mushroom | Отложить: ножка выходит за холст, размер избыточен. Светящийся вариант также слишком акцентный для массового повторения. |
| veg_glow_plant, veg_growth | Редкие декоративные акценты у Колонии после оценки масштаба/свечения, не новое здание/добываемый ресурс. |
| rock_small | Первый кандидат декора; не блокировать существующий маршрут. |
| rock_boulder, rock_boulder_ash, rock_group | Только вне маршрутов/строительных зон, либо отдельный согласованный obstacle-контракт. Большой нарисованный непроходимый объект на проходимой земле вводит игрока в заблуждение. |
| rock_cliff, rock_cave | Отложить: слишком фронтальные плоскости; нет системы высот, входа/перехода, соответствующей коллизии. Не рисовать «пещеру» как работающий переход. |
| rock_bones | Условный декоративный кандидат, вне проходов; контраст костей не должен затмевать пауков. Не боевой объект. |
| env_torch, env_fire | Декор у человеческой базы, меньше исходного масштаба; факел первый кандидат. Костёр сначала проверить нижний ореол. Это статичные изображения, не готовая анимация огня. |
| env_barrel | Кандидат уменьшенного декора, не контейнер с ресурсами/интеракцией. |
| env_wall | Отложить до контракта препятствий: фронтальная перспектива и вид непроходимой стены. |
| env_column | Условный акцент Колонии, не замена боевой башни: силуэт похож на столб, нет анимации постройки/повреждения. |
| env_crystals | Не заменять автоматически жилу эссенции: библиотечные кристаллы бирюзовые и имеют другую роль. Сначала решить визуальный язык ресурса; сейчас фиолетовая жила остаётся. |
| env_cocoon | Отложить: подвесная нить требует места крепления и иной сортировки; наземная опора (128,228) семантически спорна. Не выдавать за Инкубатор. |

## Экспорт и подключение

Рекомендуемый общий путь для текущего Canvas и будущего Phaser: SVG-источник + запечённый PNG RGBA + JSON-метаданные. Фильтры запекать один раз, не выполнять тысячи SVG-фильтров каждый кадр. У каждой записи: `id`, source hash/seed, sourceSize, pivotPx, displayScale, layer, footprint, collision, variant, acceptance status. Автоматический trim пока выключить; при trim хранить смещение и пересчитывать опору. Для атласа добавить padding/extrusion 2–4px, без потери альфы и смешивания соседних рамок.

Проверенный в этом аудите PNG-путь: `node library-review.mjs` из `tools/gamecheck` после `npm ci --ignore-scripts`. Использует уже установленный Edge/Chrome, не платные сервисы. Review-экспорт не является runtime-зависимостью игры.

### Canvas 2D (текущая игра)

Загрузить PNG через `Image.decode()`. Предмет рисовать в `(x - pivotX*scale, y - pivotY*scale, width*scale, height*scale)` внутри существующей Y-сортировки. У дерева опора — нижний центр footprint, аналогично текущему `Renderer.tree`, а не координаты верхнего левого угла тайла. Грунт запекать в `Renderer.makeTerrain`, фон не менять `world.blocked`. Декор хранить отдельно от юнитов/ресурсов/зданий. Не менять seed/random stream симуляции для случайного размещения украшений — иначе изменятся карта и баланс.

### Phaser (контракт на будущее, миграция НЕ выполнена)

API сверено по исходнику `phaserjs/phaser` tag `v3.90.0`, `src/loader/filetypes/SVGFile.js`; текущий сайт документации уже показывает v4.1.0, поэтому версия указана явно.

```js
// В Scene.preload — предпочтительный PNG-путь:
this.load.image('env.veg_pine', 'assets/env/veg_pine.png');
// Альтернатива SVG: Phaser растеризует его в bitmap texture при загрузке.
this.load.svg('env.veg_pine.svg', 'assets/env/veg_pine.svg', { width: 256, height: 256 });
// В Scene.create:
this.add.image(x, y, 'env.veg_pine')
  .setOrigin(128 / 256, 228 / 256).setScale(0.5).setDepth(y);
// Земля: .setOrigin(0, 0), отдельный слой; не тот же origin, что у предметов.
// PNG-атлас: this.load.atlas(key, pngURL, jsonURL), потом frame по id.
```

Нельзя выставить предметам origin юнитов (144/288,228/288): визуальное положение по Y сместится. Нельзя масштабировать коллизию от полупрозрачного свечения. Phaser SVG loader не оставляет бесконечно векторный объект: размер растеризации важен.

## Безопасный первый пилот (после согласования)

На существующем «Перевале», без новой карты: грунт dirt/forest и одна overlay ash, внешность нескольких существующих деревьев pine/dead, малые rock_small/dry_grass и 1–2 факела у Ордена. Существующие атласы, ресурсы, команды, поиск пути, стартовые позиции и победные условия неизменны. Сравнить юнитов на фоне в 100/50/33%, добычу у крон, выделение/полосы HP и бой в проходе. Запустить прежние экономические/боевые тесты и paired-seed серию; результаты симуляции должны совпасть. В этом аудите пилот **предложен, не внедрён**.
